# WiseGncDesign

WiseGncDesign holds Wiseware's GNC flight software in Python. It has three parts:

- the algorithms, written as literate modules;
- the C&DH (command and data handling) partition, which hosts an algorithm in a simulator;
- the analysis, which grades a recorded run's estimate against truth.

The simulated spacecraft it runs against are plant models from
[WiseDynamics](https://github.com/WisewareOrg/WiseDynamics). This repository pins WiseDynamics in
`pyproject.toml` under `[tool.uv.sources]`.

A scenario test boots an algorithm against a WiseDynamics plant, runs it, and writes one HDF5 file
per run. The analysis then reads those files. A Monte Carlo campaign is that same test run at
scale.

## Layout

| Path | What it holds |
| --- | --- |
| [`algorithms/`](algorithms/README.md) | `gnc_algorithms`: the algorithms, as jupytext-paired literate modules |
| [`cdh/`](cdh/README.md) | `gnc_cdh`: the data dictionary, and the Basilisk transport that hosts an algorithm |
| [`analysis/`](analysis/README.md) | `gnc_analysis`: the run-file loader, the error grader and the `gnc-analyze` command |
| `notebooks/` | the notebook half of each literate module, generated by jupytext |
| [`tests/`](tests/README.md) | the test tiers, including the scenario tests under `tests/sim/` |
| `docs/decisions/` | this repository's architecture decision records |

The distribution is `wise-gnc-design`. It installs the three packages `gnc_algorithms`, `gnc_cdh`
and `gnc_analysis`. It has two extras:
- `basilisk`, which adds Basilisk for `gnc_cdh.basilisk`;
- `analysis`, which adds h5py and matplotlib for `gnc_analysis`.

## Development

Every command runs from the repository root. CI runs each of them (`.github/workflows/checks.yml`).

**Install.** `uv sync --locked` installs the `dev` group:
- both extras;
- pytest and pytest-xdist;
- ruff;
- jupytext;
- a Jupyter kernel.

The `sim` group adds the pinned WiseDynamics for the scenario tests:

```sh
uv sync --locked --group sim
```

**Lint and format.**

```sh
uv run ruff check .
uv run ruff format --check .
```

**Tests.**

```sh
uv run pytest
```

This runs every tier. Without the `sim` group, `tests/sim/` skips. CI sets `REQUIRE_SIM=1`, which
turns that skip into a failure ([`tests/README.md`](tests/README.md)).

**Literate modules.** Edit either half of a module, then sync the pair and run it:

```sh
uv run jupytext --sync algorithms/gnc_algorithms/<module>.py
uv run python -m gnc_algorithms.<module>
```

Running the module executes every check and writes its figures under `figures/`. CI syncs every
pair, requires a clean tree afterwards, and runs every module
([`algorithms/README.md`](algorithms/README.md)).

### A campaign and its analysis

Run eight cases on four workers, then grade the campaign:

```sh
uv sync --locked --group sim
uv run pytest tests/sim -n 4 --sim-runs 8 --sim-out campaign
uv run gnc-analyze campaign --out report
```

What each step produces:
- each case writes `campaign/run_<NNNN>.h5`, and checks its own estimate against bounds derived
  from its drawn IMU biases;
- the session ends with the campaign check, `campaign check: 8 runs loaded from …`;
- `report/` receives `summary.md` and one figure each for attitude, position and velocity error.

The full campaign is the same command with `--sim-runs 852`, with `-n` set to the machine's core
count. The `--sim-*` options come from WiseDynamics' pytest plugin
([`tests/README.md`](tests/README.md)).
